- (decision) Paradigma: ports-and-adapters (hexagonal) no control plane + pipes-and-filters no data plane; control plane nunca no hot path.
- (decision) Identidade de telemetria: (tenant_id, project_id, signal, event_id); event_id estável e dedupe em todos os writers.
- (decision) Isolamento em profundidade: token do gateway, filtro obrigatório no Query Service, row policies no ClickHouse, bloqueio de table functions e quotas por tenant.
- (decision) Ingestão OTLP-first, at-least-once, WAL NATS JetStream; ack só após WAL; 429 com Retry-After; dedupe por event_id.
- (decision) Storage split: ClickHouse para logs/traces/eventos; VictoriaMetrics para métricas; nada de métricas no ClickHouse no MVP.
- (decision) Query Service é o único caminho de leitura; UI/API/alertas nunca falam direto com ClickHouse ou VictoriaMetrics.
- (decision) Control plane usa PostgreSQL como system of record; dashboards/alertas/config em JSONB versionado.
- (decision) Frontend SvelteKit 3 SPA servida pelo binário Go via embed; API tipada; sem acesso direto a banco.
- (decision) Open-core: binário OSS completo sem licença; features enterprise atrás de entitlement assinado; nenhum caminho de telemetria é paywalled.
- (decision) Deploy modes: single-node via Compose e cluster via Helm usam as mesmas imagens/binários; topologia diferente, contrato igual.
- (version) Go 1.27.3; ClickHouse 26.8 LTS (26.10 stable em teste); VictoriaMetrics 1.148 LTS (1.155 stable em teste); NATS 2.15.1; PostgreSQL 18.6.
